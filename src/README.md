# Apps Script への設置

`Code.gs` と `appsscript.json` を、Google スプレッドシートに紐づいた Apps Script プロジェクトに入れて使います。

## デモを動かす

1. Google スプレッドシートを新しく作り、拡張機能 > Apps Script を開きます。
2. 既定のコードを `Code.gs` の中身で置き換えます。`appsscript.json` も同じ内容にします（エディタの設定で「マニフェストを表示」をオンにすると編集できます）。
3. `CONFIG.DEMO_MODE` が `true` のまま、関数 `runScheduledPosts` を実行します。初回は権限の許可を求められます。
4. 起きること:
   - 「投稿予定」シートにサンプルが3行入ります。10分前の X と Instagram の行、24時間後の Threads の行です。
   - 日時が来た2行（X と Instagram）のステータスが「送信済(デモ)」になり、`DEMO-` で始まるダミーの投稿IDが入ります。
   - 24時間後の Threads の行は処理されず、ステータスは空のままです。
   - 「投稿ログ」シートに、処理した2行の記録が入ります。
5. もう一度実行しても、ステータスか投稿IDが入っている行は投稿しません。投稿ログにも行は増えません。

デモモードでは、どのSNSにも送りません。サンプルの本文と投稿IDは架空です。

画像URLが空の Instagram の行を過去の日時で入れて実行すると、ステータスが「エラー」になり、エラー列に理由（画像が必須）が入ります。

## 実際のアカウントに切り替える

認証情報はコードに書かず、スクリプトプロパティに入れます。Apps Script エディタの「プロジェクトの設定」>「スクリプト プロパティ」で追加します。

| 媒体 | スクリプトプロパティの名前 |
|---|---|
| X | `X_API_KEY` / `X_API_SECRET` / `X_ACCESS_TOKEN` / `X_ACCESS_SECRET` |
| Instagram | `IG_USER_ID` / `IG_ACCESS_TOKEN` |
| Threads | `THREADS_USER_ID` / `THREADS_ACCESS_TOKEN` |

1. 使う媒体の認証情報を、上の名前でスクリプトプロパティに入れます。値が無いと、その行はAPIを呼ばずに「エラー」になります。
2. `CONFIG.ENABLED_PLATFORMS` に、使う媒体だけを並べます（`'X'` / `'Instagram'` / `'Threads'`）。ここに無い媒体の行はエラーになります。
3. `CONFIG.DEMO_MODE` を `false` にします。
4. 「投稿予定」シートに行を書きます。列の見出しは次のとおりで、変えずに使います。
   - 本文 / 投稿日時 / プラットフォーム / 画像URL / ステータス / 投稿ID / 投稿URL / 送信日時 / エラー
   - ステータスから右の列はスクリプトが書き込みます。新しい行では空にしておきます。

媒体ごとの決まり:

- X は OAuth 1.0a のユーザー認証で `POST /2/tweets` を呼びます。文字数が `CONFIG.MAX_LEN.X`（280）を超える行はエラーにします。
- Instagram は画像が必須です。画像URL列に画像のURLを入れます。投稿は、メディアの作成と公開の2回の呼び出しで行います。コードの注記では、ビジネスかクリエイターのアカウントと、Meta のアプリ審査を通した権限が前提です。
- Threads は、画像URLが空なら文字だけ、画像URLがあれば画像つきで投稿します。投稿は、作成と公開の2回の呼び出しで行います。
- Instagram と Threads では、投稿URL列にリンクではなく仮の文が入ります。投稿IDは入ります。

`CONFIG.MAX_LEN` の文字数上限と `CONFIG.META_GRAPH_VERSION`（`v21.0`）は、書いた時点の値です。使う前に各社の今のドキュメントで確かめてください。

エラーになった行はステータスが残るので、次の実行でも飛ばされます。直して投稿し直すときは、その行のステータスとエラーの列を消します。

## 15分おきの自動実行

1. 関数 `setupTrigger` を1回実行します。15分おきに `runScheduledPosts` を呼ぶトリガーができます。
2. 同じ関数のトリガーが先にあれば消してから作るので、何回実行してもトリガーは1つです。

間隔を変えるときは、`setupTrigger` の中の `everyMinutes(15)` を変えます。

## 失敗の通知

1. `CONFIG.NOTIFY_ON_FAILURE` を `true` にします。
2. メールで受けるなら `CONFIG.NOTIFY_EMAIL` に宛先を入れます。Slack で受けるなら `CONFIG.SLACK_WEBHOOK_URL` に Webhook のURLを入れます。両方入れると両方に届きます。

通知は、エラーになった行ごとに1通です。中身は行番号・プラットフォーム・本文の先頭40字・エラーの内容です。
